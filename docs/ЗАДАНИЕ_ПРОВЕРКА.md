# Задание: полная проверка мода и сборки «Осколок Хаоса»

Это рабочий контекст для нового чата. Здесь всё, что нужно, чтобы продолжить без истории прошлых бесед.

## Что за проект
- Сборка «Осколок Хаоса» для Minecraft 1.12.2, Forge 14.23.5.2860. Одиночная сюжетная техно-магическая сборка: 79 модов с CurseForge и мод-ядро `chaosshard`.
- Репозиторий: GitHub `Death9051/chaosshard`, ветка `main`. Версия 0.38.0, автотест 434/434.
- Код мода: `src/main/java/ru/death/chaosshard/` (около 254 файлов, 42 тыс. строк, 36 пакетов). Ресурсы: `src/main/resources/assets/chaosshard/` (lang ru_ru/en_us, models, textures, recipes, advancements).
- Сборка (архив для CurseForge/Prism): `pack/` — `manifest.json`, `modlist.html`, `overrides/` (config, scripts, resourcepacks, DefaultQuests.json, ЧИТАЙ_МЕНЯ.md). Jar мода в `pack/overrides/mods/` не хранится, его кладут при упаковке.
- Квесты Better Questing генерируются: `python3 pack/tools/quests.py pack/overrides/config/betterquesting/DefaultQuests.json` (тексты — `pack/tools/texts.py`). 288 квестов, 14 глав, `pack_version` 67.
  - ID квеста = порядок вызова `q(...)` в списке. Новые квесты добавлять **только в конец**, иначе у старых миров собьётся прогресс. При изменении книги поднимать `pack_version`.
  - `MANUAL` — ручные координаты Акта 3; раскладка закреплена через `LAYOUT_SEED`.
  - `pack/tools/layout_render.py <DefaultQuests.json>` — картинки раскладки глав; `pack/tools/chapter_bg.py` — фоны глав.
- Сюжет и тон: `docs/БИБЛИЯ.md`. Заметки и открытые вопросы: `docs/ЗАМЕТКИ.md`.
- Список модов тестового сервера: `.github/test-mods.txt` (slug, projectID, fileID).

## Пользователь и правила
- Отвечать по-русски, чаты называть по-русски, пользователь в России (часовой пояс Europe/Moscow).
- «Тестовые блоки не трогай» / «Только блоки seed_*».
- Не деплоить на ПК, пока игра запущена. Перед записью проверить, что `logs/latest.log` заканчивается на «Stopping!/SoundSystem shutting down» и не обновляется.
- Пока пользователь тестирует, ничего не чинить без его команды.
- Сборку делать после каждого изменения. Полный серверный тест — после нескольких изменений или по просьбе. Если в jar есть непроверенное, предупреждать.
- Давать отладочные команды; пользователь для каждого теста создаёт новый мир.
- Цепочку задач выполнять автономно.
- Тексты квестов: не повторять то, что видно в JEI или в окне P; писать то, чего больше нигде нет; лор держать, а не пересказывать; голос Осколка ведёт сюжет. Мотива «в этом мире осколок уже был» нет.
- Quark и «дань едой для Обители» — пропущены намеренно.
- **Не трогать:** текстуры зверей (заяц, кошка, тигр — даст художница) и способности Тигра (согласуют другие люди). Ошибки в коде зверей чинить можно, менять дизайн способностей — нет.

## Инструменты и порядок работы
- Каждая задача — своя ветка, влить в `main` через `git merge --ff-only`. В конце сообщения коммита:
  ```
  Co-Authored-By: Claude <noreply@anthropic.com>
  ```
  (плюс строки атрибуции, которые даст система нового чата).
- Сборка в CI (локально Forge не собрать):
  `gh api -X POST repos/Death9051/chaosshard/actions/workflows/build.yml/dispatches -f ref=<ветка>`
  Затем `gh run list -w build.yml -L1`, `gh run watch <id>`.
- Серверный тест (берёт **последний собранный jar** из ветки `ci-logs`, поэтому сначала build, потом тест):
  `gh api -X POST repos/Death9051/chaosshard/actions/workflows/servertest.yml/dispatches -f ref=<ветка>`
- Логи: `git fetch -q origin ci-logs:refs/remotes/origin/ci-logs`, затем
  - `git show origin/ci-logs:build.log` — искать `error:`;
  - `git show origin/ci-logs:test/chaosshard-autotest.txt` — строки `[FAIL]` и `Итого`;
  - `test/chaosshard-registry.txt` — реестры модов сервера; `test/latest.log`, `test/console.log`.
  - Собранный jar: `git show origin/ci-logs:chaosshard-<версия>.jar > файл`.
- Автотест: `src/main/java/ru/death/chaosshard/debug/AutoTest.java` (`/oh autotest`, секции `section(...)`, шаги `step`/`until`/`check`).
- Скрипты CraftTweaker (`pack/overrides/scripts/*.zs`) на тестовом сервере **не** проверяются (там нет CraftTweaker и машин).

## Особенности Forge 1.12 и автотеста (грабли, на которые уже наступали)
- FakePlayer ненадёжно находится через `getEntitiesWithinAABB` — эффекты на сущностях проверять на зомби.
- `spawnEntity` молча не пускает сущность в незагруженный чанк — перед спавном `world.getChunk(pos)`.
- В 1.12 нет звуков `BLOCK_BEACON_*`. В `spawnParticle` писать `0.0`, а не `0`. Пакет: `pkt.getNbtCompound()`.
- `TileEntity.REGISTRY` — через `ObfuscationReflectionHelper`, поле `"field_190562_f"`.
- Cyclic регистрирует тайлы под `minecraft:` — мод тайла определять по пакету класса.
- Нежить не получает Регенерацию.
- После Акта 4 в автотесте набеги Якоря выключаются (`ChaosConfig.order.raids=false`).
- Комнаты испытаний в автотесте: `roomTicks` идёт и до старта комнаты, для проверок внутри комнаты использовать `liveTicks`.

## Доставка на ПК пользователя
Только если чат связан с компьютером (инструменты `mcp__remote-devices__*`, загружать через ToolSearch).
- Папка игры: `C:\Users\Death9051\curseforge\minecraft\Instances\_______ _____ (1)` (в device_bash — `~/mnt/*/`).
- Порядок: проверить лог (игра закрыта) → старый jar `mv` в `_to_delete/` → SendUserFile (получить fileUuid) → `device_commit_files` с `force=true`.
- Удалять файлы на ПК нельзя без разрешения — только переносить в `_to_delete/`.

## Само задание
Пройтись полностью по моду и сборке с проверкой: найти и исправить ошибки. Дизайн и баланс не менять без согласования — спорное выносить в отчёт.

1. **Автоматические сверки (сначала, самое дешёвое).** Скриптами:
   - ключи перевода: используются в коде/JSON, но нет в ru_ru или en_us; есть в одном языке и нет в другом;
   - у каждого предмета/блока есть модель и текстура, у блоков — blockstate;
   - рецепты и достижения ссылаются на существующие предметы (свои — по `ModItems`/`ModBlocks`, чужие — по `test/chaosshard-registry.txt`);
   - квесты: предметы, достижения (`adv(...)` ↔ `Milestones`/`advancements/`), зависимости без циклов и тупиков, каждый квест достижим;
   - скрипты `.zs`: все `<мод:предмет>` существуют.
2. **Чтение кода по блокам**, после каждого блока — сборка: ядро и Нить → Преддверие, Гримуар, клиент → Якоря и Скверна → ритуалы и магия → слуги и звери → логово → испытания → Акты 1–5 (структуры Ордена, герои, Гаррот, Король, Разлом, Архонт) → техника и совместимость с модами → сеть/пакеты/конфиг. Искать: падения (NPE, клиентские классы на сервере, `@SideOnly`), утечки (статические Map без очистки), неверную синхронизацию, расхождения кода с текстами квестов и lang.
3. **Проходимость сюжета:** по цепочке квестов от начала до «Завеса пала» — у каждого шага есть способ выполнения в игре. По возможности дополнить автотест.
4. **Итог:** версия 0.38.x/0.39.0, полный серверный тест, влить в `main`, обновить `pack/` (manifest version, ЧИТАЙ_МЕНЯ, квесты), собрать архив `Oskolok-Haosa-<версия>.zip` (manifest.json, modlist.html, overrides/ + jar мода в overrides/mods), отдать пользователю, при связи с ПК — разложить. Короткий отчёт: что найдено и исправлено, что спорно, что требует проверки в клиенте.
